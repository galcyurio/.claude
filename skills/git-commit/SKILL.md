# git-commit

변경사항을 눈으로 점검해 문제 여부만 판정하고, 문제가 없으면 빌드·테스트 없이 바로 커밋한다. 문제를 발견하면 커밋하지 않고 중단한다.

## 언제 사용하는가

**사용한다**

- 작업이 끝나서 working tree 의 변경을 지금 커밋하고 싶을 때
- 빌드·테스트가 느려서 커밋 단계에서는 돌리고 싶지 않을 때
- 이미 다른 방법으로 동작을 확인했고 커밋만 남았을 때

**사용하지 않는다**

- 기존 커밋 내부를 고쳐야 할 때 → `rebase-fix`
- PR까지 만들어야 할 때 → `create-pr`
- 이 변경이 실제로 동작하는지 확인받고 싶을 때 → 이 스킬은 그것을 하지 않는다

## 이 스킬이 보장하는 범위

**보장한다**: diff 에 드러나는 위험 신호를 사람이 읽듯 확인한다.

**보장하지 않는다**: 컴파일 가능 여부, 테스트 통과 여부, 런타임 동작.

따라서 커밋 결과를 보고할 때 **빌드·테스트를 실행하지 않았다는 사실을 반드시 함께 적는다.** "문제 없습니다"로만 끝내지 않는다.

## 워크플로우

### 1. 현황 수집

```bash
git status --short
git rev-parse --abbrev-ref HEAD
git diff
git diff --cached
```

- 변경이 없으면 그 사실을 알리고 종료한다.
- 브랜치명에서 이슈키(`HDA-12345` 등)를 추출한다. 없으면 이슈키 없이 진행한다.

### 2. 커밋 규칙 로드 (필수)

`~/.claude/references/commit-rules.md` 를 Read 한다.

**커밋 단위 분리와 메시지 형식은 전부 그 문서를 따른다.** 이 스킬은 그 규칙을 다시 쓰지 않고, 기억에 의존해 요약하지도 않는다. 읽지 않은 채로 커밋 메시지를 작성하지 않는다.

### 3. diff 정독과 위험 신호 탐지

`git diff --stat` 이나 파일 목록만 보고 넘어가지 않는다. **변경된 hunk 를 전부 읽는다.** diff 가 커서 한 번에 읽기 어려우면 파일 단위로 나눠 읽되, 읽지 않은 파일을 남기지 않는다.

| 범주 | 위험 신호 |
|---|---|
| 디버그 잔재 | `println`, `console.log`, 임시로 넣은 로그, 주석 처리된 코드 덩어리, 임시로 켜둔 플래그·상수 |
| 자격 증명 | API 키, 토큰, 비밀번호, 실제 계정 정보가 코드나 설정에 하드코딩 |
| 미완성 | 빈 함수 본문, 남아 있는 자리표시자, `TODO` 로 표시하지 않은 미구현, 하드코딩된 더미 데이터 |
| 사고 흔적 | `<<<<<<<` `=======` `>>>>>>>` 충돌 마커, 의도하지 않은 대량 삭제, 되돌렸어야 할 실험 코드 |
| 범위 이탈 | 이번 작업과 무관한 파일 변경, 요청하지 않은 대량 포맷팅이나 리네임 |
| 커밋 대상 아님 | `local.properties`, `.idea/`, `*.bak`, 빌드 산출물, 의도하지 않은 서브모듈 포인터 이동 |

### 4. 판정

- 위험 신호가 **하나도 없으면** → 5-A 로 간다.
- **하나라도 있으면** → 커밋하지 않고 5-B 로 간다.

### 5-A. 커밋

`commit-rules.md` 의 단위 분리 원칙대로 필요한 만큼 커밋을 나눈다. 각 커밋마다 대상 파일만 스테이징한다.

```bash
git add <이 커밋에 속하는 파일들만>
git commit -m "<commit-rules.md 형식의 메시지>"
```

- `git add -A` 나 `git commit -a` 로 뭉뚱그리지 않는다. 커밋마다 대상을 명시한다.
- 커밋이 끝나면 `git log --oneline` 과 `git status --short` 로 결과를 확인한다.

### 5-B. 중단 보고

커밋하지 않은 상태 그대로 두고 아래 형식으로 보고한다.

```
커밋하지 않았습니다. 아래를 먼저 확인해 주세요.

1. <파일:라인> — <무엇이 문제인가>
2. ...
```

발견한 문제를 임의로 수정하지 않는다. 수정 여부와 방법은 사용자가 정한다.

## 하지 않는 것

- **빌드·테스트·린트를 실행하지 않는다.** 이 스킬의 목적 자체가 그것을 건너뛰는 것이다.
- **push 하지 않는다.** `~/.claude/rules/git.md` 의 push 게이트가 그대로 적용된다.
- **문제를 발견하고도 커밋하지 않는다.**
- **발견한 문제를 임의로 고쳐서 커밋하지 않는다.**

## 합리화 방어

| 합리화 | 실제 |
|---|---|
| "빌드 한 번만 돌려보면 확실해진다" | 빌드를 돌리지 않으려고 이 스킬을 부른 것이다. 검증이 필요하다고 판단되면 커밋하지 말고 사용자에게 검증을 요청한다. |
| "diff 가 기니까 `--stat` 만 봐도 충분하다" | 위험 신호는 hunk 안에 있다. 길면 나눠 읽되 전부 읽는다. |
| "로그 한 줄쯤은 사소하니 그냥 커밋한다" | 사소한지는 사용자가 판정한다. 발견하면 보고하고 멈춘다. |
| "내가 고쳐서 커밋하면 사용자 시간을 아낀다" | 임의 수정은 요청 범위 밖이다. 보고하고 판단을 받는다. |
| "커밋 규칙은 이미 아니까 파일은 안 읽어도 된다" | 규칙은 갱신된다. 매번 `commit-rules.md` 를 읽고 그 내용으로 쓴다. |
| "커밋까지 됐으니 push 도 해준다" | push 는 사용자의 명시적 지시가 있을 때만 한다. |
| "문제가 있지만 다음 커밋에서 고치면 된다" | 문제가 히스토리에 남는다. 커밋 전에 멈추는 편이 되돌리기 쉽다. |

## 보고 형식

커밋에 성공하면 아래 두 가지를 반드시 포함한다.

1. 만든 커밋 목록 (`git log --oneline` 결과)
2. **빌드·테스트를 실행하지 않았다는 명시**

예:

```
커밋 2개를 만들었습니다. 빌드와 테스트는 실행하지 않았습니다.

  a1b2c3d HDA-12345 feat: 로그인 실패 시 재시도 버튼을 노출한다
  e4f5g6h HDA-12345 test: 재시도 버튼 클릭 시 재요청하는지 확인한다
```
