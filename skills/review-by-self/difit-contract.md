# difit 공유 계약

`review-by-self` · `review-by-agents`가 공통으로 따르는 difit 뷰어 실행·수명·회수 계약이다. 각 스킬은 difit를 다루는 단계에서 이 파일을 Read해 아래를 따르고, 스킬 고유 부분(`--comment` 프리로드·게이트·회수 해석)은 각 SKILL.md가 정의한다.

## `<difit-command>` 선택

- `command -v difit` 성공 → `difit`
- 실패 → `npx difit`
- 샌드박스에서 네트워크 권한이 없어 `npx difit` 실행이 막히면, 권한 상승을 요청하고 사용자 승인 후 실행한다.

## 실행 — nohup detach (포그라운드 호출)

- `nohup <difit-command> <인자…> > <스크래치패드>/difit-<N>.log 2>&1 &` 형태로 **평범한 포그라운드 Bash 호출 안에서 detach**한다. **하니스 백그라운드(`run_in_background`)를 쓰지 않는다.**
- 이유: `run_in_background` + `--keep-alive`는 **끝나지 않는 하니스 태스크**를 남긴다. 그 잡이 exit하는 순간은 회수 후 우리가 kill할 때뿐이라, 리뷰가 준비된 뒤에도 `/tasks`·Tasks 패인에 계속 `running`으로 남아 **사용자가 리뷰 준비 완료를 인지할 수 없다**. `nohup … &`는 호출 셸이 끝나면 `PPID=1`로 재부모화돼 살아남으므로(실측: 호출 종료 후는 물론 **턴 경계를 넘긴 다음 턴에도** HTTP 200 · `comment get` 정상), 추적 태스크 없이 서버가 턴을 넘어 유지된다. `PGID`는 호출 셸 그룹에 남지만 그것 때문에 죽지는 않는다.
- **difit 자체 `--background` 플래그는 쓰지 않는다.** 실측으로 확인된 두 가지 결함이 있다:
  - `--background`는 자식을 `stdio: ['ignore', …]`로 spawn하고 **부모가 stdin을 읽기 전에** 넘긴다 → **stdin diff가 조용히 무시되고 `HEAD^..HEAD`로 대체된다.** 6파일 stdin diff를 파이프했는데 데몬은 2파일 리비전 diff(`b25d03b...1159a8e`)를 렌더했다. PR 모드가 **엉뚱한 diff를 리뷰하게 되므로 치명적**이다.
  - `--port`가 점유되면 stdout에 `Port <N> is busy, trying <N+1>...` 한 줄만 나오고 **JSON이 나오지 않아** URL·pid를 확정할 수 없다.
- **stdin으로 diff를 넣는 모드(PR 등)는 파이프가 아니라 파일 리다이렉트로 준다.** detach된 프로세스에 파이프를 물릴 수 없으므로 diff를 스크래치패드 파일에 먼저 받고 `< <patch 파일>`로 넣는다(실측: `commit label: stdin diff` · 파일 수 일치).
- **`--no-open`을 붙인다.** difit가 브라우저를 직접 열지 않고 **사용자가 URL을 열게** 한다. 이렇게 하면 브라우저가 difit의 자식 프로세스가 아니므로, 회수 후 서버를 안전하게 종료할 수 있다(아래 "회수 후 종료" 참고).
- **`--keep-alive`를 붙인다.** 사용자가 브라우저를 닫아도 difit가 자가 종료하지 않고 서버·코멘트를 메모리에 유지한다. 회수 트리거는 브라우저 닫힘이 아니라 **사용자의 반영 요청이나 종료 신호**다(아래 "회수" 참고). 이 플래그를 빼면 브라우저 탭이 닫힐 때 difit가 코멘트를 stdout에 덤프하고 자가 종료하지만, 그 트리거가 heartbeat SSE 연결 끊김이라 **새로고침이나 페이지 이동에도 서버가 죽는다**(`server.js`의 `/api/heartbeat` → `outputFinalComments()` → `process.exit(0)`). 리뷰 도중 세션이 끊기는 편이 더 나쁘므로 `--keep-alive`를 유지하고, 세션 종료 시 정리는 아래 "세션 종료 자동 정리 — 지킴이"에 맡긴다.
- **URL·pid 확정은 로그 파일로 한다.** 런치 1~3초 후 로그를 읽어 `🚀 difit server started on http://localhost:<port>` 배너에서 **실제 바인딩 포트**를 확인한다(`--port <N>`이 점유되면 difit가 다음 포트로 옮기고 배너에 그 포트가 찍힌다). pid는 `lsof -ti tcp:<port> -sTCP:LISTEN`으로 얻어 기록한다 — "회수 후 종료"에 쓴다. **`-sTCP:LISTEN`을 빼면 접속 중인 브라우저 pid까지 섞여 들어온다**(아래 "회수 후 종료" 참고). 배너가 아직 없으면 다시 읽는다.

## 세션 종료 자동 정리 — 지킴이

`nohup … &`로 detach했으므로 difit는 **클로드 세션이 끝나도 혼자 계속 켜져 있다.** 하니스가 정리해 주지 않으므로, 리뷰 결과에 반영할 것이 없어 사용자가 곧바로 세션을 닫으려는 상황에서 **오직 서버를 끄게 하려고 "리뷰 완료"를 알려야 하는 불필요한 왕복**이 생긴다.

그래서 difit를 띄운 직후 **이 세션의 `claude` 프로세스를 감시하는 지킴이를 함께 detach로 띄운다.** 세션이 사라지면 지킴이가 difit를 대신 종료한다.

- Bash 도구가 실행하는 셸의 `$PPID`가 **이 세션의 `claude` 프로세스**다(실측: `ps -o pid,ppid,command -p $PPID` → `claude`, 그 위가 로그인 셸과 터미널 앱). 이 값을 감시 대상으로 쓴다.
- 런치 배너로 포트를 확정하고 `lsof`로 difit pid를 얻은 **직후**, 같은 Bash 호출 안에서 띄운다.

```bash
DIFIT_PID=$(lsof -ti tcp:<N> -sTCP:LISTEN)
nohup bash -c "while kill -0 $PPID 2>/dev/null && kill -0 $DIFIT_PID 2>/dev/null; do sleep 5; done
  P=\$(lsof -ti tcp:<N> -sTCP:LISTEN 2>/dev/null)
  [ \"\$P\" = \"$DIFIT_PID\" ] && kill \"\$P\"" >/dev/null 2>&1 &
```

- `$PPID`와 `$DIFIT_PID`는 **바깥 셸에서 전개**되어 감시 대상이 값으로 박히고, `\$P`는 지킴이 내부에서 전개된다. 이스케이프를 바꾸면 감시 대상이 엉뚱한 프로세스가 된다.
- **pid와 포트를 함께 확인한 뒤 죽인다.** difit가 이미 정상 종료되어 pid가 재사용되고 그 포트를 다른 프로세스가 점유한 상황에서 무관한 프로세스를 죽이지 않기 위한 조건이다.
- **감시 조건에 difit pid도 넣는다**(`kill -0 $PPID && kill -0 $DIFIT_PID`). 이것이 없으면 6-D 회수 경로로 difit를 먼저 끈 뒤에도 지킴이가 세션이 끝날 때까지 빈 루프를 돌고, 한 세션에서 리뷰를 여러 번 하면 그만큼 쌓인다. 두 조건을 함께 보면 **difit가 먼저 사라진 경우 지킴이도 곧바로 물러난다**(실측: difit를 먼저 kill하면 5초 내 지킴이 자가 종료, 잔존 프로세스 0개).
- 루프를 빠져나온 뒤 포트를 다시 확인하므로, difit가 먼저 죽은 경우에는 pid가 일치하지 않아 아무것도 죽이지 않는다.
- 세션이 **강제 종료되거나 다운되어도 동작한다.** `kill -0` 폴링이라 종료 신호를 받을 필요가 없다.
- 정리 지연은 최대 5초다. 즉시 정리가 필요하면 회수 경로("회수 후 종료")를 쓴다.

이 지킴이가 있으므로 **사용자에게 종료를 위한 신고를 요구하지 않는다.** 안내는 "반영할 것이 있으면 알려달라"까지이고, 반영할 것이 없으면 사용자는 아무 말 없이 세션을 닫으면 된다(아래 "회수" 참고).

## 코멘트 영속과 세션 격리 — `--clean`

difit는 리뷰 코멘트를 **브라우저 localStorage에 영속**하며, 이 저장소는 **origin(`localhost:<port>`) 단위**다. 클라이언트는 로드 시 그 origin에 쌓인 이전 코멘트를 모두 복원하므로, 같은 포트로 difit를 다시 띄우면 **이전 세션·다른 PR의 코멘트가 이번 diff에 섞여** 나타난다(회수 시에도 그대로 포함된다).

- 매 리뷰를 깨끗한 상태로 시작하려면 **`--clean`을 붙인다.** 서버가 `/api/diff` 응답에 `clearComments:true`를 실어 보내고, 클라이언트가 로드 시 `clearAllComments()`로 localStorage를 비운다.
- `--clean` 없이 세션을 열면 leak이 발생한다. **프리로드·회수를 쓰는 스킬은 `--clean`을 기본으로 한다.**
- `--clean`은 해당 origin의 **모든** 저장 코멘트를 지운다(현재 diff/PR 한정 아님). 의도적으로 이전 코멘트를 이어서 볼 때만 생략한다.

## 회수 — 사용자의 반영 요청 + `comment get`

difit는 코멘트를 **서버 메모리에 보관**한다(브라우저가 코멘트를 실시간으로 서버에 저장하고, `--comment` 프리로드도 세션에 담긴다). `--keep-alive`로 띄웠으므로 브라우저를 닫아도 서버·코멘트가 남아, **실행 중 서버에서** 코멘트를 조회할 수 있다.

- 회수 트리거는 **사용자가 반영을 요청하거나 리뷰가 끝났다고 알리는 것**이다. detach 실행이므로 **기다릴 하니스 잡이 아예 없고, 브라우저 닫힘을 폴링하지도 않는다.** 런치 후에는 사용자에게 "브라우저를 열어 리뷰하고, **반영할 것이 있으면** 알려달라"고 안내한 뒤 턴을 종료한다.
- **반영할 것이 없어 사용자가 아무 말 없이 세션을 닫는 경로가 정상이다.** 이때 회수는 일어나지 않고 지킴이가 서버만 정리한다. 서버를 끄기 위한 신고를 요구하지 않는다(위 "세션 종료 자동 정리 — 지킴이" 참고).
- 신호를 받으면 `difit comment get --port <N> --format text`로 실행 중 서버에서 코멘트를 회수한다. 출력은 아래 포맷이다(difit 내부의 동일한 `formatCommentsOutput` 결과).

```
📝 Comments from review session:
==================================================
<file>:L<line>
<첫 메시지 본문>
Reply <N> (<author>)
<답글 본문>
==================================================
Total comments: <N>
```

- thread는 `==================================================` 구분선 사이에 `<file>:L<line>`(범위면 `L<start>-L<end>`) + 첫 메시지 본문으로 나온다. thread가 여러 개면 thread 사이는 짧은 `=====` 구분선으로 나뉜다.
- 사용자 답글은 그 아래 `Reply <N> (<author>)` 라벨 + 본문으로 붙는다.
- 마지막 줄은 `Total comments: <N>`. 블록이 없거나 `Total comments: 0`이면 남긴 코멘트 없음이다.
- 구조화 파싱이 필요하면 `--format json`으로 `{version, threads:[…]}` 형태를 받는다.

## 회수 후 종료

`--no-open`으로 띄웠으므로 브라우저는 difit의 자식 프로세스가 아니다. 따라서 코멘트를 회수한 뒤 **우리가 이번에 띄운 그 서버 프로세스를 종료**해 정리한다. 지킴이가 세션 종료 시점을 받치고 있지만 그것은 최대 5초 지연되는 백스톱이므로, **회수를 한 경우에는 이 자리에서 즉시 종료한다.**

- **반드시 `comment get`으로 회수를 먼저 끝낸 뒤 종료한다.** 종료가 먼저면 코멘트를 잃는다.
- 종료는 **우리가 쓴 그 포트를 LISTEN하는 프로세스에 한정해** 한다: `kill $(lsof -ti tcp:<우리 포트> -sTCP:LISTEN)`. 종료할 하니스 잡이 없으므로 잡 종료로는 정리되지 않는다.
- **`-sTCP:LISTEN`을 빼면 사용자의 브라우저가 함께 종료된다.** `lsof -ti tcp:<port>`는 그 포트를 LISTEN하는 서버뿐 아니라 **그 포트로 연결을 맺고 있는 클라이언트 프로세스의 pid까지 반환한다**(실측: 서버 pid와 접속 중인 클라이언트 pid가 함께 출력됨). difit 탭을 열어 둔 브라우저가 바로 그 클라이언트이므로, 필터 없이 kill하면 소켓을 쥔 브라우저 프로세스가 죽어 **브라우저 창 전체가 닫힌다.** `-sTCP:LISTEN`을 붙이면 LISTEN 소켓을 가진 difit 서버만 남는다(실측 확인).
- `pkill difit`처럼 포트를 특정하지 않고 무관한 difit 서버(다른 세션·다른 리뷰)까지 죽이는 명령은 **쓰지 않는다.**

## 시크릿 금지

토큰·비밀번호·API 키·개인키·PII 등 자격증명류를 `--comment` 본문이나 명령줄 인자에 **절대 복사하지 않는다.**
