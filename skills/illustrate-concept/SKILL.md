# 설명용 이미지 그리기

설명을 그림으로 그려 PNG로 내보낸다. 이 스킬의 책임은 **그릴지 판단하고, PNG를 만들어 눈으로 검증하는 데까지**다. 업로드와 본문 삽입은 호출한 쪽이 맡는다.

## 1. 그릴지 말지 먼저 판단한다

**기본은 그리지 않는 것이다.** 그림은 맥락을 모르는 독자가 글만 읽고는 머릿속에서 조립해야 하는 구조를 한눈에 보여 줄 때만 가치가 있다. 문장 하나가 더 빨리 전달하면 문장을 쓴다.

| 설명할 것 | 수단 |
|---|---|
| 문장 1~3개로 전달된다 | 글 |
| 단계·분기·호출 순서·상태 전이 | mermaid (`flowchart`, `sequenceDiagram`, `stateDiagram-v2`) |
| 공간 배치, 겹침·포개짐, 화면 모양, 전후 비교, 일상 비유 구조 | 이 스킬로 그린다 |

판단이 애매하면 mermaid를 먼저 써 본다. 써 놓고 보니 **리뷰어가 알아야 할 사실이 그림에서 빠진다**면 그때 이미지로 간다.

예: 공유 요소 전환에서 `ComposeView`(줌 화면)와 대역 `ImageView`(전환용 사진)가 같은 자리에 포개져 있고 전환 순간에만 교대한다. `stateDiagram-v2`로 교대 규칙은 그려지지만 "같은 자리에 두 장이 겹쳐 있다"는 공간 사실이 빠지므로 이미지가 맞다.

글이나 mermaid로 결정했으면 이 스킬은 거기서 끝난다. mermaid 블록이나 글을 호출한 쪽에 돌려준다.

## 2. 무엇을 그릴지 정한다

- **이름이 아니라 동작을 그린다.** `캐시`라고 적힌 상자 하나는 글보다 정보가 적다. 설명이 기대는 부분(넘는 경계, 추가되는 단계, 움직이는 데이터, 포개진 위치)만 그리고 나머지는 뺀다.
- **비교라면 차이를 그린다.** 각 선택지·전후가 더하거나 빼는 요소를 독자가 손으로 짚을 수 있어야 한다. 아무것과도 연결되지 않은 상자를 선택지마다 하나씩 두는 것은 목록을 다시 적은 것이지 비교가 아니다.
- **복잡도는 결정이 좌우되는 범위에 맞춘다.** 한 단계짜리 질문은 상자 3개면 되고, 시스템 전체 목록을 그리지 않는다.
- **화살표에는 레이블을 붙인다.** 레이블 없는 화살표는 "어떻게든 관련 있음"밖에 전하지 않는다 (`덮음`, `교대`, `30초마다 확인`).
- 그리기 전에 **이 그림이 주장하는 한 문장**을 정한다. 그 문장이 검증 단계의 기준이 된다.

## 3. 작도 규칙

- 캔버스: `viewBox="0 0 1200 {600~800}"`, `width`·`height`도 같은 값, 배경은 흰색 `<rect>`.
- 색: 회색 계열(`#DADCE0`, `#9AA0A6`, `#5F6368`) + 강조 1색. 강조색은 **설명의 주인공인 도형과 그 라벨에만** 쓴다. 단계 제목·화살표·범례는 회색으로 둔다.
- 글자: 22px 이상, `font-family="-apple-system, 'Apple SD Gothic Neo', sans-serif"`. 문장이 아니라 라벨 수준으로 짧게 쓰고, 설명 문장은 그림 밖(본문)에 둔다.
- 큰 도형 + 짧은 라벨. 상자 같은 주요 도형은 패널 하나당 7개 이하로 두고, 화살표·글자는 세지 않는다. 도형은 공통 기준선과 같은 간격에 맞춰 정렬한다.
- **겹침을 보여줄 때는 겹치는 폭을 도형 너비의 절반 이상으로 준다.** 살짝 엇갈리게 두면 "나란히 놓인 둘"로 읽힌다. 뒤 도형은 점선 테두리, 앞 도형은 실선으로 선 종류로도 앞뒤를 구분한다. 실제로는 완전히 같은 좌표에 있더라도 이렇게 어긋나게 그리고, "같은 자리"라는 사실은 제목이나 라벨로 적는다.
- **앞 도형이 덮는 자리에 라벨이나 강조 요소를 두지 않는다.** 뒤 도형의 라벨은 겹치지 않는 바깥쪽에 둔다.
- 전후 비교는 왼쪽 `변경 전`, 오른쪽 `변경 후`로 두고 바뀐 부분만 강조색으로 칠한다.
- `<script>`, 외부 이미지, `<foreignObject>`를 쓰지 않는다. 화살촉은 `<marker>`나 작은 `<polygon>`으로 그린다.

## 4. 절차

1. **Chrome 확인**: `test -x "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`. 실패하면 이미지를 포기하고 mermaid나 글로 돌아간다.

2. **SVG 작성**: Write로 `/tmp/explain-images/{주제 슬러그}/{nn}-{슬러그}.svg`에 쓴다. Write는 `$TMPDIR` 같은 셸 변수를 전개하지 않으므로 경로에 변수를 쓰지 않는다. 작업 레포 안에 만들지 않는다.

3. **PNG 변환**:

   ```bash
   perl -e 'alarm 20; exec @ARGV' -- "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
     --headless=new --disable-gpu --hide-scrollbars --no-first-run \
     --user-data-dir=/tmp/explain-images/{주제 슬러그}/.chrome --force-device-scale-factor=2 \
     --window-size=1200,{높이} --screenshot=/tmp/explain-images/{주제 슬러그}/{nn}-{슬러그}.png \
     "file:///tmp/explain-images/{주제 슬러그}/{nn}-{슬러그}.svg"
   ```

   Chrome은 PNG를 쓴 뒤에도 프로세스가 끝나지 않아 `alarm`으로 끊는다. 그래서 **종료 코드로 성공을 판정하지 않고, PNG 파일이 생겼는지로 판정한다.** `Trying to load the allocator multiple times` 같은 stderr 경고는 무시한다. `qlmanage`는 정사각형으로 잘라내므로 쓰지 않는다.

4. **눈으로 검증한다**: 생성된 PNG를 Read로 열어 직접 본다. 파일이 생겼다고 그림이 맞는 것이 아니다.
   - 2단계에서 정한 한 문장이 그림만 보고 읽히는가
   - 글자가 잘리거나 도형 밖으로 넘치지 않는가
   - 겹침·앞뒤 관계가 의도대로 읽히는가
   - 강조색이 주인공에만 칠해져 있는가
   - 라벨이 다른 도형에 가려지지 않았는가

   하나라도 어긋나면 SVG를 고쳐 3번부터 다시 한다. 처음 그린 것을 검증 없이 내보내지 않는다.

5. **전달**: PNG 절대 경로를 별도 라인에 출력한다. 사용자에게 직접 보여 주는 경우 `SendUserFile`로 보낸다. PR 본문에 넣을 때는 호출한 쪽이 `upload-pr-image` 스킬로 URL을 받는다.

## 실패 시

Chrome이 없거나 변환·검증이 끝내 통과하지 못하면 이미지를 포기하고 mermaid나 글로 대체한다. 이미지 때문에 호출한 쪽 작업을 멈추거나 사용자에게 되묻지 않는다.
