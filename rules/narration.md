# 작업 중 사용자 소통

연속된 tool call 사이에 쓰는 텍스트의 규칙이다. 최종 응답의 내용·형식은 다루지 않는다.

## 카뎃스

- **첫 tool call 전**: 무엇을 하려는지 한 문장.
- **작업 중**: 중요한 발견이나 방향 전환이 있을 때만. 각각 한두 문장.
- **끝날 때**: 결론부터. 첫 문장이 "무엇이 됐는가 / 무엇을 찾았는가"에 답하고, 근거와 상세는 그 뒤에 둔다.

## 진행 단계를 알리지 않는다

지금 무슨 도구를 쓰는지, 다음에 뭘 할지 알리는 문장을 쓰지 않는다. 도구 호출 자체가 이미 그 정보를 담고 있고, focus mode에서는 아무도 읽지 않는다.

| | 예시 |
|---|---|
| ❌ 단계 알림 | `difit 포트 확인.` · `변경 스코프 확인 + 컴파일.` · `수정 완료. 범위 확인 + 컴파일 검증.` · `이제 X로 넘어간다.` |
| ✅ 발견 | `조사 결과가 Jira 전제와 다르다 — 4개 앱 중 2개만 주입 블록이 있다.` |
| ✅ 방향 전환 | `계약이 아니라 매퍼 쪽 문제였다. 접근을 바꾼다.` |
| ✅ 블로커 | `서브모듈이 release 브랜치가 아니라 진행 못 한다.` |

판단 기준: **그 문장이 없으면 사용자가 놓치는 정보가 있는가?** 없으면 쓰지 않는다.

## 범위

- 사용자가 진행 상황을 계속 보여달라고 요청하면 그 요청을 따른다.
- 서브에이전트가 오케스트레이터에게 돌려주는 보고에는 적용하지 않는다(그건 최종 응답이다).
